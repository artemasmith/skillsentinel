# Detection rules

Generated from [`rules/rules.json`](../rules/rules.json) — 46 rules as of catalog v0.3.4 (`python3 -m skillsentinel rules` prints the live count). Do not hand-edit; regenerate instead.

Every rule match is a **candidate**, not a finding. A file-local verifier (`skillsentinel/verifier.py`) then confirms or demotes it — every demotion carries a written reason in the output. Severity below is the *candidate* severity from the catalog; confirmed findings keep it, demoted ones are reported as `low_trust`.

**Documentation is an instruction surface.** Six rules carry `doc_surface` (SS001, SS002, SS004, SS006, SS007, SS008): they are graded the same way in a plain `README.md` as in a `SKILL.md`. A specimen stays a *written* demotion only when it is marked structurally — a fenced block, inline `code`, or a quoted citation with a citation frame (`it says "..."`). A bare quote with no frame is the file acting. Dual-use primitives are untouched: a `curl | bash` install instruction or a crontab/`authorized_keys` line in prose stays `capability`.
